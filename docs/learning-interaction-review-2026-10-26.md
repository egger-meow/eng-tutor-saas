# 學習區互動體感改善與驗收（2026-10-26）

以使用者提供的畫面作為問題起點，範圍涵蓋本週教材、歷史教材、家長觀察與閱讀完成頁。延續既有紙色、深綠與字體，沒有新增 UI 套件、變更生成流程或教材內容。

## 問題與改動

| 原本的操作阻力 | 現在的行為 |
| --- | --- |
| 原生小三角與文字標題沒有明確的操作範圍 | 整列可點的展開控制，含提示、展開／收起文字、旋轉箭頭、hover／按下／鍵盤焦點狀態 |
| 展開內容直接跳出，畫面位置突然改變 | 約 240ms 高度與透明度過場；尊重減少動態效果設定 |
| 回饋入口在大片留白的右下角，和觀察說明分離 | 統一的家長觀察區，清楚的補充／修改按鈕；手機上為整行按鈕 |
| 選項的 label 和 span 同時有膠囊邊框與 padding | 移除雙層外框，統一單層選項與選取指示，點擊範圍至少 44px 高 |
| 首頁與完成頁使用不同的難度／加強輸入模式 | 都以可直接點選的選項呈現，不需要打開選單 |
| 收起回饋就銷毀輸入，儲存後入口缺少回應 | 在同一教材頁內收起仍保留草稿；儲存顯示成功訊息、返回入口焦點；失敗保留文字供重試 |
| 內部課綱 ID 與規劃術語直接顯示給家長 | 已知用語轉為家長可讀的中文；未知 ID 使用中性描述，不捏造能力名稱或修改原始證據 |
| 數字看完沒有附近的下一步 | 加入明確的回教材複習入口，靜態統計本身不假裝可點 |

截圖檢視另發現完成頁「稍後再填」繼承了白色按鈕文字，已改用可辨識的次要操作樣式。

## 真實瀏覽器操作與截圖

使用正式元件與路由，在本地 Chromium 執行 `node scripts/test-feedback-flow-browser.mjs`。API 是 stateful synthetic RPC，並刻意注入讀取／儲存錯誤；不是正式家庭資料、真人可用性研究或手機實機證據。

1440×1000、390×844、320×844 全流程通過：部分提交、略過、申請下一份、首頁新增／修改、重新整理讀回、歷史教材與完成頁修改、服務月上限、失敗／取消、讀取錯誤與重試、歷史紙本入口。

此次新增的操作驗證：

- 點擊展開列的最右側仍能操作，按鈕高度至少 44px。
- 正常動態設定下量測展開中間高度，確認非瞬間跳變；Space／Enter 可切換。
- 減少動態效果下使用零或近零過場。
- 首頁與完成頁收起後再開啟，未儲存文字不遺失。
- 儲存後焦點回到入口；儲存失敗可直接重試。
- 閉合內容不進入鍵盤操作順序；200% 文字與 320px 螢幕無水平溢出。
- 家長畫面不顯示測試中的內部課綱 ID 與 evidence-backed 術語。
- 回饋儲存不增加教材申請次數，且保留家長既有完成比例。

實際檢視桌面展開前／後、手機表單、完成頁截圖。輸出位於 `.runtime/feedback-flow/`：

- `*-dashboard-card.png`：家長觀察區與收合狀態。
- `*-rationale-card.png`：展開後的調整說明。
- `*-dashboard-feedback.png`：首頁填寫觀察。
- `*-reader-feedback.png`：閱讀完成頁編輯。
- `results.json`：逐尺寸操作結果。

原閱讀器瀏覽器回歸腳本亦通過 320px／390px／820px／1440px；涵蓋儲存、離線、衝突、提交後解答、TTS 入口與申請。
